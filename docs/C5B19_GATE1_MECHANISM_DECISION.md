# C5b19 gate-1 mechanism decision candidate

Date: 2026-09-19. Owner: Capsule maintainer. Status: `IN_PROGRESS — TRENDING_GOOD` for this prospective design; gate 1 remains `BLOCKED` on independent review. This is a documentation-only decision packet, not implementation or child-run authorization.

## Question and authorized boundary

Can one current-lifetime Supervisor control lane retain exact direct-child custody and meet the C5b17 stop/absence bounds while one post-create durable write is blocked? Scope is the fixed inert child, owned disposable local directories and separately authorized macOS host described in the [experiment plan](C5B19_BENIGN_TEARDOWN_EXPERIMENT_PLAN.md). No guest, daemon, backend, network, user content, installed service, or unrelated PID is in scope. The exact run host and fixture bytes remain gate-2 work.

## Decision for independent review

**Recommend two anonymous Darwin pipes, one fixed request and one fixed reply, between one native control lane and one precreated storage worker.** A separate one-event, attempt-bound local harness pipe supplies the defensive cancellation fixture to control; it is not a production cancel API. The pipes transport data, not authority: only control owns spawn, start, stop, signal, wait/reap, clocks and admission of a reply; only worker calls the Go bridge and store. The child receives none of these pipes. One frozen operation per attempt and one outstanding operation total are state-machine limits even if a kernel pipe could hold more bytes. This is a `BUILD-NARROWLY` framing over `ADOPT-PLATFORM` transport candidate, not a selected product dependency.

| Option | Disposition | Reason |
| --- | --- | --- |
| Anonymous pipes with fixed frames | Recommend for gate-1 review | Kernel byte transport avoids a new cross-language atomic-memory protocol; nonblocking control endpoints and a single outstanding-operation invariant bound control work independent of storage. |
| Shared C11 atomic slot | Defer | Requires an additional lock-free and C/Go memory-order proof for no advantage established by this bounded case. |
| Mutex/condition mailbox shared with worker | Reject for this case | A worker-held lock or condition wait could put storage back on the stop path. |
| Helper, daemon or independent watchdog | Reject | Would add a lifecycle owner/authority outside ADR-0047; fixture alarm is containment only. |

## Frozen prospective control graph

1. **Before spawn:** resolve one immutable prepared obligation and receive a confirmed durable result. Configure all three exchange/cancellation pipes and the separate start gate before worker or child creation: `FD_CLOEXEC`, nonblocking control request-write/reply-read/cancel-read/start-write, nonblocking worker reply-write, and `F_SETNOSIGPIPE` on every write descriptor including the start gate. Verify each exchange frame length is at most 512 bytes and at most the queried `_PC_PIPE_BUF`; failure closes creation. Construct the sole worker before child creation. Any setup failure is no-spawn.
2. **Create:** only control calls `posix_spawn` for the fixed child with `POSIX_SPAWN_CLOEXEC_DEFAULT` and an explicit start-gate descriptor allowlist. On success it records the positive returned PID in current-lifetime custody; on failure it never interprets the PID output. The child cannot fork/exec and starts gated.
3. **Publish identity:** control freezes obligation, operation ID, generation, kind and entire candidate before one nonblocking request write. `EAGAIN`, `EPIPE`, partial/zero write or unexpected descriptor state is a fatal control fault; no retry with changed bytes and no start. Worker reads exactly one complete frame, rejects invalid/duplicate input, calls exactly one `BridgeApply` under its existing bridge/store locks and posts one exact result. Worker cannot perform any process operation or publish a start token. If its reply pipe is full/broken, it may remain pending; control never depends on its progress for stop.
4. **Service:** control samples the one clock, drains at most the one fixed cancellation event from its nonblocking harness pipe and validates its attempt binding, then checks setup/wall/fatal triggers and latches stop **before** inspecting a ready reply. A caller-supplied timestamp has no authority: `t_cancel` is the control lane's actual accepted ingress tick. After immediate checks, `poll` may pace on cancellation/reply readiness for at most 1 ms and no longer than the next control deadline; `EINTR` re-enters sampling immediately and an error is a fatal fault. This bounded multiplexing is independent of worker completion: no path waits for a reply to service stop, and the loop can advance on timeout with no reply. Control uses only nonblocking descriptor operations; it never calls Go/store, takes bridge/store locks, waits on a worker condition, or joins the worker while custody exists. A full/closed pipe cannot block stop. Exact tuple and settled-result equality are required before applying a reply. Control captures `t_start` immediately before its one nonblocking start-token attempt, serialized by this same lane, after durable identity publication and only without a stop latch. A closed or full start gate is a fault, never a retry that resets `t_start`. Late reply cannot reopen it.
5. **Stop:** control checks same-parent exclusive-reaper preconditions, calls `waitpid(pid, ..., WNOHANG)` for only its retained child, and, only if that reports live, sets its one-signal-attempt latch *before* one positive-PID `kill`. It continues exact-child nonblocking wait/reap observation. A matching terminal status establishes `t_absent`; `kill` return, `ESRCH`, EOF, an alarm, or `ECHILD` does not. No retry, PID adoption or other-target probe. Stuck storage leaves owner lock and completion closed, but not the native stop path.

The worker may use blocking reads and store calls because it has no lifecycle authority. The harness cancel writer may send at most one fixed event, and a duplicate/full/broken event pipe is a recorded fixture fault, never a second stop authority. No second request is sent until the first settles and its reply is consumed; no storage write after native absence is assumed to complete. Cleanup/join after absence must be specified and bounded in gate 2; an indefinitely blocked worker never becomes a successful terminal join.

### Frame budget and failure rules

Frames use explicit network-order fields and byte arrays, never native struct layout, pointers, paths or PID targets. A **provisional upper-bound worksheet**, not the final encoding: header/version/length 4; C5b18 bindings 240; obligation digest 32; operation ID 16; generation 8; kind 1; candidate at most 68; outcome 1; clock-policy binding 24; trigger mask 1 = **395 bytes**. Gate 2 must freeze each request/reply schema, prove both actual maxima independently at or below `min(512, _PC_PIPE_BUF)`, and reject this option if that cannot be done without fragmentation. No variable-length payload, padding, queued second frame or replacement candidate is permitted. A short read is assembled into one bounded frame by the sole worker/control reader; EOF mid-frame, excess byte, duplicate, version/tuple mismatch or late conflicting result is refusal/uncertainty, never success. Nonblocking write of one frame no larger than `PIPE_BUF` must be all-or-`EAGAIN` under the cited platform contract; any observed partial write is nevertheless fatal. `F_SETNOSIGPIPE` prevents a broken pipe from killing the Supervisor; `EPIPE` remains a recorded fault.

The provisional candidate-size number above is a budget assumption, not a claim that the C5b18 model has an on-wire format. Gate 2 must map every C5b18 frozen field and any additional binding exactly; an omitted field or over-budget mapping reopens gate 1. No new third-party package is proposed.

## Custody, signal and clock premises

The [pinned C5b16 source](https://github.com/Shrimpworks/capsule-experiments/tree/0efd03def6bc333a92c8b9809bc56b7b3ce9ea80/experiments/typed-guest-transport-c5b16-timing-fault/source) contains a native `waitpid(WNOHANG)`/`kill` owner and read-only `SIGCHLD` disposition checks; the Go bridge holds `bridgeMu` across store calls. A read-only inventory of that pinned source found no competing waiter, `signal.Notify`, or process-wide signal-disposition writer. This is old-source evidence, **not** linked-successor closure. Gate 4 must inventory every linked C/Go/generated source, initialization path and runtime interaction for `wait*`, `SIGCHLD` changes, `SA_NOCLDWAIT`, auto-reap, and competing owner; it must prove the actual parent still retains exclusive wait status. If the precondition fails, no signal or absence claim.

The exit-before-signal argument remains conditional: an exited but unreaped child retains its PID until the owning parent waits under the [POSIX process-lifetime rule](https://pubs.opengroup.org/onlinepubs/9799919799/basedefs/V1_chap04.html). Thus a successful positive-PID `waitpid(..., WNOHANG)==0` followed by an exit before `kill` should not redirect the one signal to a reused PID **only while** default `SIGCHLD`, no `SA_NOCLDWAIT`, same parent and exclusive waiter all hold. `ECHILD` or changed disposition destroys that inference. The guard and raw-event oracle must test natural exit before signal and error paths; no numeric-PID-only trust.

Use `mach_continuous_time()` for all same-lifetime anchors and observations, including setup expiry, `t_start`, actual wall service, cancel ingress, action, force and absence. Capture one nonzero `mach_timebase_info` before spawn. Compare a checked nonnegative raw-tick difference using unsigned 128-bit products, `(now-anchor)*numer >= bound_ns*denom`, rather than converting to rounded milliseconds or adding a potentially overflowing due tick; overflow/refusal closes timing claims. Enforce `now >= last_observed_tick` and record both raw ticks and ratio. Sleep counts; a wake or scheduler delay that services wall/setup late is a timing failure, not a fresh budget. No uptime/continuous mixed anchors. The setup clock begins at endpoint creation and has the existing 1,000-ms C5b16 limit; C5b17/C5b18 action and force bounds remain unchanged. Gate 2 must freeze timer pacing and actual service sampling; gate 4 must prove those exact implemented paths. This is a clock accounting policy, not a scheduler guarantee.

## Independent raw-event oracles to freeze at gate 2

The checker derives status from raw operation, frame, ingress, clock, spawn, wait and store events, never from a fixture success flag. In each row, missing authoritative events remain null/failure; harness containment is labeled separately.

| Controlled fixture/fault | Required independent rejection or observation |
| --- | --- |
| Preparation pending/refused/unknown | No spawn or worker publication. |
| Store blocks before runner-identity publication; cancel or setup expiry | Start remains shut; actual control stop and exact absence remain measurable without reply. |
| Reply late or same tick as cancel/wall/fatal | Stop wins; no start, capacity or completion release. |
| Child exits between live `waitpid` and signal | One latched signal attempt at most; later exact status proves absence, not `kill` return. |
| Injected `ECHILD`, `ESRCH`, changed `SIGCHLD` or competing-reaper observation | No invented absence, PID retry or alternative target; custody-failure result. |
| `EAGAIN`, `EPIPE`, EOF, short/excess/duplicate frame, tuple mutation | Start refusal and uncertainty; no second operation or worker-origin authority. |
| Lost signal response or lost store response | No signal redrive; exact wait status may prove absence, store uncertainty remains. |
| Suspend/wake, late clock service or regressed tick | Original continuous-time budget retained; timing failure or explicit unmeasured classification, never pass. |

Relevant mutants must restore stop-to-store wait, second request/signal, late start, forged absence, substituted frozen candidate or rounded/restarted clock and be caught by this checker. Gate 2 must freeze exact fault sites and oracle schema; gate 4 independently reviews implemented bytes before any owner-authorized child run.
