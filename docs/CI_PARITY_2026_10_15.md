## Gate boundaries

Local CI must cover dependency audit, site/schema/ADR checks, exported JSDoc for changed
TypeScript files, TypeScript build/type/lint/tests, and Go format/vet/lint/vulnerability/tests/build.
Dependencies are installed first with `pnpm install --frozen-lockfile` and the documented pins.
A local run does not reproduce GitHub dependency-review, CodeQL, immutable-archive retrieval,
action execution, branch protection, or nightly scheduling. Local Go tests run the full suite;
the normal hosted Go job uses `-short`, with a separate scheduled full-suite job.

Go security and correctness lint remains whole-code. Revive uses changed lines, preserving
CI's existing #217 rollout policy. JSDoc uses entire changed files, so an undocumented export
in a selected file still fails even when the export itself was not edited. Full documentation
audits remain available and their pre-existing backlog is not declared resolved.

The pinned [golangci action implementation](https://github.com/golangci/golangci-lint-action/blob/ba0d7d2ec06a0ea1cb5fa41b2e4a3ab91d21278a/src/run.ts)
uses event-specific patches for `only-new-issues`. Local comparisons therefore need a valid
base and matching tree to reproduce that scope; they cannot claim identical GitHub event metadata.
[pnpm script forwarding](https://pnpm.io/10.x/cli/run) supports explicit built-output test commands
while retaining build-safe standalone entrypoints.

Reproduce focused tests with:

```sh
node --test scripts/ci-parity.test.mjs scripts/verify-exported-jsdoc.test.mjs
node --test scripts/ci-parity-go.integration.mjs
```

The second command requires the documented Go pin and golangci-lint 2.12.2. It is deliberately
separate from the TypeScript-only script test glob, whose runner does not install the Go linter.
Fixtures are disposable local Git repositories; the security-negative fixture uses only a
synthetic TLS configuration and performs no network requests. No complete-backlog or product
security-readiness claim follows from these contributor-workflow checks.

Review instance 1 found that golangci-lint 2.12.2 can retain absolute finding paths from another
checkout in shared caches. Two retained repositories with identical modules reproduced a new
undocumented export failing in the first root and passing in the second; a separate linter cache
restored rejection with the same Go cache. The finding was accepted. Cache isolation belongs in
the local wrapper, not only the test fixture, because ordinary worktrees can encounter it too.
The unchanged G402 negative still failed; no general security-linter bypass is claimed.

The correction namespaces the linter cache by SHA-256 of the canonical checkout path, below
a caller-selected `GOLANGCI_LINT_CACHE` parent or Git's per-checkout metadata cache directory.
It verifies cache accessibility, reuses entries within that checkout and never clears the
caller's existing cache. Both retained roots now reject the undocumented change on repeated
runs sharing a cache parent. The regression was red before this correction and green afterward.
The first scan in a checkout must warm its own cache; subsequent scans retain normal reuse.

[Review instance 1](../.planning/ci-parity-265/review-1.md) returned Not ready; the finding was
accepted and corrected. [Review instance 2](../.planning/ci-parity-265/review-2.md) returned Ready
with no remaining actionable findings after independent positive/negative checks and evidence
reconciliation. The corrected full aggregate passes. `make lint-go-full` still reports the
same 50 capped revive findings and exits nonzero, confirming that the separate debt audit remains active.
