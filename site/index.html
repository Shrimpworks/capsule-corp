capsule

Human-approved execution for agent code.

Capsule is building a narrow owner-only alpha for macOS: one byte-exact modern main.mjs module, bounded inline JSON input and output, one-use human approval, and one fresh disposable Linux/arm64 guest per attempt.

What Capsule is

Capsule is intended to provide a small local execution service for bounded, one-shot work—not a general computer. Planning, approval, and execution belong to separate components so the agent-facing service cannot approve its own plan or launch a guest.

The first internal alpha is JavaScript-only: exactly one dependency-free main.mjs, at most 262,144 bytes, with bounded inline JSON. TypeScript, package installation, module loading, network access, subprocesses, inherited environment variables, native add-ons, FFI, file artifacts, and live host paths are deliberately deferred or refused.

What Capsule is not

Capsule is not a shell, development environment, general-purpose virtual machine, or hosted sandbox. It does not determine whether generated code is correct, and it cannot prevent approved output, metadata, or timing from revealing approved input.

How the intended system works

The design separates planning, human approval, and execution so the agent-facing service does not control all three.

Daemon
Agent-facing planning service
Validates proposals, resolves trusted policy, and constructs exact plans. It is not allowed to approve a plan or launch a guest.
Approval Broker
Trusted native approval interface
Fetches registered typed plan data, presents it to the user, requires fresh user presence, and signs one-use approval.
Execution Supervisor
Trusted execution authority
Registers exact plan bytes, enforces hard safety rules, creates one approved attempt, and owns backend cleanup and enforcement evidence.
Isolation backend
External host boundary
Contains the guest outside the language runtime. Runtime permission systems are only supplemental hardening.

What is implemented today

Capsule has moved beyond an initial scaffold, but it is not yet a usable sandbox. Status below separates completed engineering slices from active integration and product blockers.

PASSED — scoped foundations
Exact contracts, durable mechanics, and governed build evidence
Single-main.mjs bytes and manifests; plan and registration codecs; approval/attempt, lifecycle, owner-lock, archive, backup, and recovery mechanics; governed Deno, rusty_v8, and libkrun forks; reproducible Linux/arm64 runtime artifacts; and development-signed inactive macOS topology have passed their stated local scopes.
IN_PROGRESS — TRENDING_GOOD
Successor runtime profile and authority-path integration
Current work is freezing the runnable profile, atomically binding source to registered plans, reviewing the production CBOR/COSE wrapper, hardening governed-fork promotion, and joining the already-tested pieces without widening authority.
BLOCKED — product admission
No hostile-code alpha or admitted runtime/profile yet
Capsule still needs one fixed benign guest checkpoint, authenticated local IPC, protected installed Supervisor state, native Broker rendering and fresh user-presence signing, a real adapter with restart reconciliation, composed completion evidence, and the retained hostile/refusal corpus. The fake backend remains hard-coded to create no guest.

Security requirements

These are requirements for the intended security model, not claims about the current implementation.

Separated authority
Planning, approval, and execution have different owners
Registered plans only
Execution accepts a Supervisor-issued plan ID, never replacement plan bytes
One-use approval
Human approval is bound to one exact plan and at most one execution attempt
Immutable input
File inputs become content-addressed snapshots instead of live host paths
External isolation
Every approved attempt gets a fresh disposable guest; guests are never reused
Physical absence
The alpha runtime must omit module loading and ambient host operations
Independent completion
Guest output, EOF, or exit zero cannot prove success without teardown evidence
