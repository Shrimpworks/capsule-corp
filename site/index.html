capsule

No ambient authority.

A runtime boundary for agent-generated work.

Capsule is an experimental trusted execution platform for bounded JavaScript and TypeScript jobs. An agent proposes work, a daemon plans and registers exact bytes, a trusted Broker obtains human authorization, and only the Execution Supervisor may create the hostile guest.

Open the repository → Read the project brief →

The agent proposes. The daemon plans. The Broker approves exact registered bytes. Only the Supervisor creates the guest.

Core rule

One job. Five explicit stages.

The first slice is dependency-free JSON so every authority stays testable.

  1. 1.0

    Propose.

    The agent submits source, requested inputs, limits, and expected outputs.

  2. 2.0

    Plan & register.

    The daemon resolves exact authority. The Supervisor stores and revalidates those bytes.

  3. 3.0

    Approve.

    The native Broker renders the registered plan and signs one attempt-bound grant.

  4. 4.0

    Execute.

    The Supervisor consumes approval once and owns the disposable backend lifecycle.

  5. 5.0

    Release.

    The Broker releases bounded content; the receipt composes approval and enforcement claims.

The language runtime is not the boundary.

Planning, human authorization/content custody, and backend execution are separate authorities. External isolation still contains the hostile guest.
